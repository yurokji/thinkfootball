Think Football
==============

Production Game Specification v1.0
----------------------------------

* * *

0\. 게임 개요 (High-Level Definition)
---------------------------------

### 장르

*   **전략 시뮬레이션 게임 (Strategy Sports Simulation)**
*   실시간 진행, **직접 조작 없음**
*   플레이어는 “감독/전술가”의 역할만 수행

### 핵심 정체성 문장 (Design Pillar)

> **Think Football is a strategic football game  
> where the player does not control players or outcomes,  
> but shapes the probability space of victory.**

* * *

1\. 게임의 목표 (Game Goals)
-----------------------

### 1.1 플레이어의 목표

플레이어는:

*   개별 선수의 조작이나 타이밍을 컨트롤하지 않는다.
*   대신 **전술, 포지션, 선수 조합, 위험 감수 수준**을 통해  
    **경기에서 유리한 확률 분포를 만들려고 시도**한다.

승리는:

*   “완벽한 컨트롤”의 결과가 아니라
*   **확률적 우위가 누적된 결과**로 발생한다.

* * *

### 1.2 게임이 제공해야 하는 경험

*   “왜 이 골이 나왔는지” 설명 가능한 축구
*   “실력”이 아니라 **판단과 설계**가 축적되는 경험
*   짧은 순간의 반응 속도보다 **전반적인 전략 일관성**이 보상받는 구조

* * *

2\. 장르적 경계 선언 (Non-Goals)
-------------------------

Think Football은 다음을 **의도적으로 하지 않는다**:

*   직접 선수 조작 (키보드/마우스/패드로 드리블, 슛)
*   정밀 물리 시뮬레이션 기반 판정
*   반사신경 중심의 아케이드 플레이
*   “공이 머리에 닿았는지”를 충돌 계산으로 판단

이로 인해:

*   FIFA, PES, Rocket League류 게임과 명확히 구분된다.
*   Think Football은 **전술 전략 게임**이다.

* * *

3\. 핵심 설계 원칙 (Core Design Principles)
-------------------------------------

### 3.1 확률 중심 설계

*   모든 주요 이벤트는 **확률 사건**이다.
*   전술은 “행동을 명령”하는 것이 아니라  
    **확률 분포를 변형하는 수단**이다.

### 3.2 물리 최소화 원칙

*   물리 시뮬레이션은:
    *   연출
    *   상태 전환
    *   시간 흐름 표현  
        에만 사용한다.
*   결과 판정은 **규칙 + 능력치 + 상황**으로 결정한다.

### 3.3 설명 가능성

*   모든 성공/실패는:
    *   선수 능력
    *   전술 선택
    *   상황 변수  
        로 설명 가능해야 한다.
*   “왜 졌는지/이겼는지”를 사후 분석할 수 있어야 한다.

* * *

4\. 기술 아키텍처 개요
--------------

### 4.1 엔진 분리 원칙

Think Football은 두 개의 독립 레이어로 구성된다.

1.  **Game Core Engine (Simulation Engine)**
2.  **Rendering / UI Engine**

이 둘은 **강하게 분리**된다.

* * *

### 4.2 Game Core Engine (필수)

*   C++ 기반 순수 시뮬레이션 라이브러리
*   결정론적 업데이트 (고정 timestep)
*   렌더링, 입력, UI에 의존하지 않음

#### 책임

*   월드 상태 관리
*   선수/공 상태 업데이트
*   AI(Team / Group / Player Brain)
*   확률 판정(Outcome Sampling)
*   이벤트 생성 (패스, 트랩, 헤딩, 태클)
*   저장/로드(JSON)
*   리플레이(RNG 시드 포함)

* * *

### 4.3 Rendering / UI Engine

*   raylib + rayGUI 권장
*   2.5D 탑다운 표현
*   모든 연출은 **Core 결과를 시각화**하는 역할만 수행

* * *

5\. 월드 모델 (World Model)
-----------------------

### 5.1 좌표계

*   3D 좌표계 사용
    *   X: 좌우
    *   Z: 전후 (공격 방향)
    *   Y: 높이(연출용)

### 5.2 전술/공간 판단

*   모든 전술 판단은 **XZ 평면(2D)** 기준
*   Y(높이)는:
    *   공중볼 여부 판단
    *   연출 파라미터  
        로만 사용

* * *

6\. 피치 구역 시스템 (Pitch Zoning System)
-----------------------------------

### 6.1 기본 구조

*   가로: **5 Lane**
    *   Left Wing / Left Half-space / Center / Right Half-space / Right Wing
*   세로: **4 Band**
    *   Defensive / Mid-Defensive / Mid-Attacking / Attacking

→ 총 **20개 기본 Zone**

### 6.2 특수 구역

*   Penalty Area
*   Zone 14 (박스 바로 앞 중앙)
*   Byline Cross Zone

### 6.3 용도

*   전술 판단
*   위험도 계산
*   확률 가중치 조정
*   UI 시각화

* * *

7\. 선수 모델 (Player Model)
------------------------

### 7.1 Player 구성

*   PlayerState (위치, 속도, 소유 여부)
*   PlayerStats (능력치)
*   PlayerCondition (피로, 압박)
*   PlayerIntent (행동 의도)
*   PlayerBrain (AI)
*   Movement (실행기)

### 7.2 능력치 원칙

*   능력치는 **결과 확률에만 영향**
*   능력치가 낮다고 “이상 행동”을 하지 않는다.
*   대신:
    *   성공 확률 ↓
    *   오차 ↑
    *   실수 이벤트 ↑

* * *

8\. AI 구조 (AI Hierarchy)
------------------------

### 8.1 TeamBrain

*   팀 단위 전술 파라미터 제공
*   라인 높이, 압박 강도, 위험 감수

### 8.2 GroupContext (국소 상황 요약)

*   공 주변 국면 요약
*   수적 우위/열세
*   압박 정도
*   전술적 기회 여부

> GroupContext는 판단하지 않는다.  
> **요약만 제공한다.**

### 8.3 PlayerBrain

*   개별 선수 판단 주체
*   TeamContext + GroupContext + 개인 능력 기반 결정
*   Intent 생성

* * *

9\. 행동 판정 시스템 (Outcome Sampling)
--------------------------------

### 9.1 패스

*   의도 목표점 선택
*   패서 능력 기반 오차 적용
*   실제 도착점 생성

### 9.2 땅볼 패스

*   잔디 물리 없음
*   “튐/불안정성”을 **노이즈 파라미터**로 표현
*   리시버 트래핑 확률에 영향

### 9.3 크로스/롱패스

*   패서 로빙 정확도 → 크로스 품질
*   리시버 점프/타겟/헤딩 → 접촉 확률
*   충돌 계산 없음

### 9.4 헤딩

*   “맞았는지”는 확률 판정
*   결과:
    *   성공(온타겟/클리어)
    *   빗맞음
    *   헛빵

* * *

10\. Movement 시스템
-----------------

### 10.1 역할

*   Brain이 만든 Intent를
*   능력치/피로 제약 하에 실행

### 10.2 책임 범위

*   이동
*   회전
*   간격 유지(separation)
*   점프 연출

### 10.3 비책임

*   판정
*   전술 판단
*   결과 결정

* * *

11\. UI / UX 목표
---------------

### 11.1 감독 시점

*   플레이어는 “판단자”로 존재
*   조작 피드백보다 **정보 피드백**이 중요

### 11.2 제공 정보

*   존 점유
*   위험 지역 침투 빈도
*   박스 진입 횟수
*   슈팅/기회 흐름

> 승률 수치를 직접 보여주지 않는다.  
> 대신 **확률을 암시하는 지표**를 제공한다.

* * *

12\. 디버그 / 개발 요구사항
------------------

*   모든 Intent 시각화
*   Zone 오버레이
*   확률 판정 로그
*   리플레이 지원
*   RNG 시드 고정 가능

* * *

13\. 성공 기준 (Definition of Done)
-------------------------------

Think Football v1.0은 다음이 충족되면 성공이다.

1.  직접 조작 없이도 경기 흐름이 “축구처럼” 보인다.
2.  전술 변경이 **결과 분포**에 명확한 영향을 준다.
3.  패배 원인이 설명 가능하다.
4.  물리 없이도 공중볼/트래핑이 납득된다.
5.  플레이어는 “판단이 쌓였다”는 감각을 느낀다.

* * *

14\. 최종 선언
----------

Think Football은:

*   스포츠 게임이지만
*   조작 게임이 아니다.

이 게임의 핵심은:

*   **승리를 만드는 손놀림이 아니라**
*   **승리를 설계하는 사고**다.

이 명세는 변경되지 않는 **프로덕션 기준선**이다.  
이 문서를 기준으로, 구현은 바로 시작될 수 있다.
